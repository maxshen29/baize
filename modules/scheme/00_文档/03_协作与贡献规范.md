# 03 · 协作与贡献规范

> 保证多人协作时目录、命名、模板与知识条目的质量一致性。开发前即确立，避免后期返工。

## 1. 目录与编号

- 平台根下只允许 `00_文档`~`05_代码` 六个顶层编号目录，新增一级模块需评审。
- 文档统一 `NN_主题.md`；能力模块设计统一 `NN_模块设计_能力名.md`。
- 新增模板放入 `02_模板/`，新增知识条目放入 `04_知识库/知识条目/`，导入文档放入 `03_参考文档/导入物/`。

## 2. 命名规范

- 目录/文件名使用「数字序号_中文语义」或「类型_名称」，避免空格，用下划线连接。
- 模板类型前缀：`投标方案_`、`技术方案_`、`实施方案_` 等，便于按场景检索。
- 知识条目文件：`KE_<YYYYMMDD>_<主题简称>.md`。

## 3. 文档质量

- 每个文档首行用 `# NN · 标题` 表示层级。
- 关键设计结论需给出「职责 / 接口 / 数据结构 / 关键决策」四要素。
- 涉及外部参考（如 OpenBidKit）须注明来源链接与对应模块。

## 4. 模板与知识条目

- 模板必须含元数据头（见 `02_模板/10_模板元数据规范.md`），否则不入库。
- 知识条目必须标注来源文档与切片位置（溯源），无来源的人工条目需标注 `confidence`。

## 5. 版本与评审

- 方案/设计文档的实质性修改应更新顶部「变更记录」。
- 能力④生成内容进入人工定稿前，须经项目经理或知识管理员审校。

## 6. 贡献流程（开发后启用）

1. 提 Issue 描述需求/缺陷。
2. Fork / 分支开发。
3. 提交 PR，附「影响的能力模块 + 自测说明」。
4. 评审通过后合入。
