# 00 · 平台概述

> 本文件是 `00_文档` 模块的第一篇，用于向新成员/协作者快速说明 Baize 方案撰写平台「是什么、解决什么问题、怎么用」。

## 1. 背景与痛点

写方案（投标方案、技术方案、实施方案、可研报告等）长期存在三类痛点：

1. **结构靠记忆**：每次都要从零搭章节，容易漏项、格式不统一。
2. **素材散落**：企业资质、历史中标方案、规范条文分散在各类文件里，临写时找不到、对不齐。
3. **重复劳动**：相似方案反复手工拼装，质量不稳定，且难以保证内容「有出处、可追溯」。

## 2. 平台要解决什么

把「写方案」拆成可复用、可沉淀、可检索、可生成的四层能力：

- **模板层**：固定「结构」，让任何人都能套用成熟骨架。
- **文档层**：把参考材料统一解析、入库、管理。
- **知识层**：把文档变成「可检索的知识点」，支撑生成时引用。
- **撰写层**：依模板 + 知识，按需生成章节，人工只需定稿。

> **技术栈（已确定）**：前端 Vue3 + Vite + TypeScript；后端 FastAPI(Python)；数据库 PostgreSQL 16 + pgvector（元数据与向量一体）。详见 `01_方案/08_技术选型与工程规范.md`。

## 3. 与参考项目的关系

本平台借鉴 [OpenBidKit_Yibiao](https://github.com/FB208/OpenBidKit_Yibiao) 的成熟实践：

| OpenBidKit 中的对应物 | 本平台抽象为 |
| --- | --- |
| `templateStore` / `templateExtractionTask` | 能力① 参考结构模板 |
| `doc2markdown` / `knowledgeBaseService` 导入 | 能力② 参考文档管理 |
| `knowledgeBaseStore`（含 search） | 能力③ 可检索知识库 |
| `contentGenerationTask` / `outlineGenerationTask` / `agentService` | 能力④ 按需撰写引擎 |

差异点：本平台**不绑定招投标场景**，模板/知识条目的元数据结构更通用，可作为任意「方案类写作」的基础平台。

## 4. 适用角色

- **方案工程师**：套模板、选知识、生成与定稿方案。
- **知识管理员**：导入并维护参考文档、校对知识条目。
- **项目经理**：把控范围、审校、导出交付物。
- **平台维护者**：维护模板库与系统配置。
