# 04 · 模块设计 · 参考文档管理（能力②）

> 变更记录：2026-09-18 初版。对应目录 `03_参考文档`。

## 1. 职责

- 导入各类源材料（Word/PDF/Markdown/网页/图片），解析为 Markdown/纯文本。
- 管理文档元数据、版本、去重与检索预览。

## 2. 核心流程

```
导入文件/链接 → 选择解析方式(本地/MinerU)
   → 解析为 Markdown(保留标题层级)
   → 补全元数据(来源/类型/日期/标签/密级)
   → 去重(checksum) → 入库(03_参考文档/导入物)
   → [触发] 知识库切片(见 05)
```

## 3. 文档数据结构（草图）

```yaml
reference_document:
  id: doc_xxx
  title: 某公司资质证明文件
  source_type: word | pdf | markdown | webpage | image
  original_path: 03_参考文档/导入物/xxx.docx
  parsed_path: 03_参考文档/导入物/xxx.md
  status: parsed | failed
  checksum: sha256:...
  tags: [资质, 公司A]
  classification: 公开 | 内部 | 机密
  version: 1
  imported_at: 2026-09-18
  chunks: 42            # 供知识库切片
```

## 4. 解析策略

- **常规文档**：`mammoth`（docx）→ md；`pandoc`（通用）→ md。
- **复杂 PDF/扫描件**：MinerU 或 OCR 兜底，保留版面与表格。
- **网页**：抓取正文（Readability 类）后转 md。
- 解析失败保留原文件并标记 `status=failed`，可重试。

## 5. 关键接口（规划）

- `POST /documents/import`（含解析方式参数）。
- `GET /documents?tag=&type=` 检索；`GET /documents/:id` 预览。
- `POST /documents/:id/version` 新版本；`DELETE /documents/:id` 归档。

## 6. 关键设计决策

- **解析与原文分离**：存原文 + 解析文本，便于重解析与溯源。
- **去重前置**：导入即算 checksum，避免知识库重复污染。
- **失败可恢复**：参考 OpenBidKit 的「后台任务落盘、可恢复」思路，长解析任务异步化。
