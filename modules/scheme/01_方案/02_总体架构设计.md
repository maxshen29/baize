# 02 · 总体架构设计

> 变更记录：2026-09-18 初版。

## 1. 设计目标与原则

- **分层解耦**：表现 / 应用 / 领域 / 基础设施 / 数据 五层。
- **能力独立可演进**：四大能力各自成服务，互通过明确接口。
- **本地优先**：默认数据在本地，云端为可选协作增强。
- **AI 网关化**：模型调用统一经网关，支持多家与本地模型。

## 2. 分层架构

```
┌─────────────────────────────────────────────┐
│  表现层 (Presentation)                        │

┌───────────────────▼─────────────────────────┐
│  应用服务层 (API Gateway)                      │
│  模板API · 文档API · 知识库API · 撰写API · 导出API│
└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  领域服务层 (Domain Services)                  │
│  TemplateService │ DocumentService            │
│  KnowledgeBaseService │ WritingService(Agent) │
│  CheckService │ ExportService                 │
└──────┬──────────┬──────────┬─────────┬───────┘
       │          │          │         │
┌──────▼──────────▼──────────▼─────────▼───────┐
│  基础设施层 (Infrastructure)                   │
│  Storage(文件+元数据) │ Vector/Search Index    │
│  Parser(doc→md) │ LLM/Embedding Gateway       │

└───────────────────┬─────────────────────────┘
                    │
┌───────────────────▼─────────────────────────┐
│  数据层                                        │

```

## 4. 四大能力数据流

```
[模板]──▶ 初始化撰写任务骨架
                     │
[参考文档]──解析──▶[知识库]──检索──▶[撰写引擎]──▶[方案草稿]
     │                  ▲                │
     └────────溯源──────┴────────引用────┘
                              │
                          [检查/导出]
```

- 模板决定「写什么结构」；文档经解析进入知识库；撰写时按章节检索知识并生成；生成内容回链溯源。

## 5. 与 OpenBidKit 架构对照

| OpenBidKit | 本平台（确定栈） |
| --- | --- |
| `client/electron`（Main/Preload/Renderer，React+TS） | 前端 Vue3 + Vite + TS（Web） |
| `electron/services/*Service.cjs` | 后端 FastAPI features/* Service |
| `knowledgeBaseStore` / `templateStore` | PostgreSQL 表（pgvector 存向量） |
| `doc2markdown` | Python 解析（python-docx/pypdf/MinerU） |
| `contentGenerationTask` + `agentService` | WritingService（FastAPI + LangGraph 编排） |
| `sqliteDatabase.cjs`（SQLite） | PostgreSQL 16 + pgvector |

差异：本平台将「知识库检索」「文档管理」显式独立为能力②③，并在元数据上做通用化抽象。

## 6. 部署形态（确定）

- **形态：Web 平台**。前端 `web/`（Vue3）+ 后端 `api/`（FastAPI）+ 数据库 PostgreSQL(pgvector)。
- **本地优先**：`docker-compose.yml` 一键拉起 Postgres+pgvector；前端 `npm run dev`、后端 `uvicorn`。
- **可团队协作**：同一套后端与数据库可部署到内网/云服务器，前端共用。
- 表现层与领域服务通过 REST/WebSocket 解耦，未来若需离线桌面壳可再包 Electron，不影响后端。

## 7. 关键设计决策

1. **先关键词后语义**：检索先保证可用（BM25/全文），再叠加向量召回，降低早期风险。
2. **切片单位 = 知识条目**：以「章节/段落」为粒度，兼顾语义完整与溯源精度。
3. **Agent 编排而非单提示**：撰写采用「大纲→逐章→检查」多步编排（借鉴 Pi Agent 的 Runtime/Session 思路），支持中断恢复。
4. **强制溯源**：生成内容默认携带引用，关不掉，保证可审校。

## 8. 安全与隐私

- 原始文档默认本地存储，不上传；云端仅用于可选协作。
- AI 网关可指向自托管/本地模型，敏感内容不外发。
- 知识条目带密级标签，检索时按权限过滤（远期）。
