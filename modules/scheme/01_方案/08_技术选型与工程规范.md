# 08 · 技术选型与工程规范

> 变更记录：2026-09-18 初版；2026-09-18 更新为确定栈 **Vue3 + FastAPI + PostgreSQL(pgvector)**。

## 1. 技术栈总览（已确定）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | **Vue 3 + Vite + TypeScript** | 组合式 API；Pinia 状态、Vue Router 路由 |
| UI 组件 | Element Plus 或 Naive UI | 表单/表格/树/抽屉，贴合后台类界面 |
| 后端 API | **Python 3.11+ FastAPI** | Pydantic v2 校验、SQLModel/SQLAlchemy ORM |
| 关系库 | **PostgreSQL 16** | 主数据库，存模板/文档/知识条目/任务元数据 |
| 向量/检索 | **pgvector**（Postgres 扩展） | 语义向量 ANN + Postgres 全文(tsvector) 混合检索 |
| 解析 | python-docx / pypdf(PyMuPDF) / markdownify / MinerU(可选) | doc→md，复杂 PDF 走 MinerU |
| 嵌入 | **本地模型**：Ollama 托管 `bge-m3`/`bge-small-zh`；云端备选 OpenAI text-embedding | 本地优先，敏感不出域 |
| LLM | 统一 LLM 网关：OpenAI-like / Ollama 本地模型 | 生成与 Agent 编排共用 |
| Agent 编排 | LangGraph（或自研状态机） | 大纲→逐章→检查多步 |
| 后台任务 | FastAPI BackgroundTasks + 持久化任务表 | 解析/生成可恢复 |
| 导出 | python-docx / pandoc | Word/PDF，保留引用 |
| 工程 | Docker Compose（PG+pgvector）、Alembic 迁移、pytest、pre-commit | 本地一键起 |

> 选型准则：**本地优先、可替换、可检索**。模型与嵌入均为可插拔；数据库统一用 Postgres，避免双写。

## 2. 为什么这套组合

- **Vue3 + FastAPI**：前后端分离清晰，TS 前端与 Python AI 生态无缝衔接，团队技能通用。
- **Postgres + pgvector**：一个库同时存「结构化元数据 + 向量」，省去额外向量库运维；FTS 与向量在同一事务内混合检索，溯源简单。
- **本地嵌入（bge-m3）**：支持中英多语、维度适中（1024），Ollama 本地推理零成本、零外发。
- **LangGraph**：把「大纲→逐章→检查」显式建模为图，便于中断恢复与可观测。

## 3. 与 OpenBidKit 技术栈对照

| OpenBidKit | 本平台（确定栈） |
| --- | --- |
| Electron Main/Preload/Renderer | Vue3 Web 前端（Vite） |
| Vite+React+TS+Radix | Vue3+Vite+TS+Element Plus |
| SQLite（`sqliteDatabase.cjs`） | PostgreSQL 16 + pgvector |
| `doc2markdown` | Python 解析（python-docx/pypdf/MinerU） |
| Pi Agent Runtime/Session | FastAPI + LangGraph 编排 |
| Open XML 助手（.NET） | python-docx 导出 |

差异：本平台用 **Web + Postgres** 替代桌面 + SQLite，更利于团队检索与知识库常驻；知识库检索与文档管理显式独立为能力②③。

## 4. 工程规范

### 4.1 仓库布局（单体仓 monorepo）
```
方案系统/
├── web/        # Vue3 前端（对齐 02_模板/03_参考文档/04_知识库/撰写 UI）
├── api/        # FastAPI 后端（features: template/document/knowledge/writing/check/export）
├── db/         # SQL 迁移（Alembic）与 pgvector 初始化、seed
└── docker-compose.yml  # postgres+pgvector 本地一键起
```

### 4.2 命名规范
- 目录/文件：`NN_语义` 或 `类型_名称`，下划线连接、无空格。
- 模板类型前缀：`投标方案_`/`技术方案_`/`实施方案_`。
- 知识条目：`KE_<YYYYMMDD>_<主题>.md`（文档化条目）；DB 中以 `chunks` 表存储。

### 4.3 文档规范
- 每文档首行 `# NN · 标题`；含「变更记录」。
- 设计文档含：职责 / 接口 / 数据结构 / 关键决策 四要素。
- 引用外部需注明来源链接。

### 4.4 提交与测试
- 模板/条目入库前须通过元数据校验（`02_模板/10_模板元数据规范.md`）。
- 生成内容导出前需经检查（一致性/废标/查重）。
- `api/` 单测覆盖解析、切片、检索；用 pytest。

## 5. 安全基线
- 原始文档默认存本地 Postgres + 本地文件；嵌入/LLM 可指向本地 Ollama，敏感内容不出域。
- 知识条目密级标签参与检索过滤（远期）。
- `.env.example` 提供配置样例，密钥不入库。
