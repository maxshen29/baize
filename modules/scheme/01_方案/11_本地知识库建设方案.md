# 11 · 本地知识库建设方案

> 变更记录：2026-09-18 初版。承接 `05_模块设计_知识库.md`，给出「本地优先」知识库的可落地建设方案。

## 1. 目标与原则

- **本地优先**：文档、向量、模型推理全部可在本机/内网完成，敏感资料不出域。
- **一个库搞定**：用 PostgreSQL + pgvector 同时存结构化元数据与向量，免去独立向量库运维。
- **可离线**：嵌入与 LLM 均可指向本地 Ollama，无外网也能构建与检索。
- **可溯源**：每条知识能回链到原文档与切片位置。

## 2. 总体流程

```
导入文档 ─▶ 解析(doc→md) ─▶ 切片(Chunk) ─▶ 嵌入(Embedding)
                                                      │
                                                      ▼
                        PostgreSQL: documents + chunks(向量+FTS) ◀─ 检索请求
                                                      │
                                      混合检索(FTS+向量+分面) ─▶ 结果(带溯源)
```

## 3. 解析策略（infra/parser）

| 来源 | 工具 | 要点 |
| --- | --- | --- |
| Word(.docx) | `python-docx` | 提取标题层级、表格、列表 |
| PDF(文本) | `pypdf` / `PyMuPDF` | 按页/按块提取，保留版面 |
| PDF(扫描) | MinerU / OCR | 版面+表格识别，质量优先 |
| 网页 | `markdownify` + readability | 抓正文转 md |
| Markdown/文本 | 直接读取 | 按标题切分 |
| 图片 | OCR（可选） | 仅关键图 |

解析产物统一为 **Markdown（保留 `#` 标题层级）**，作为切片输入。

## 4. 切片策略

- **按标题层级递归切片**：以二级/三级标题边界切分，保证单块语义完整。
- **重叠窗口**：相邻块尾部重叠 100~200 字，避免跨块语义断裂。
- **大小约束**：单块 300~800 字；超长段落再按句边界二次切。
- **保留元数据**：每块记录 `document_id`、`heading_path`（如「三、技术方案 > 3.1 架构」）、`chunk_index`、`char_start/end`。
- **可人工校正**：自动切片生成的候选条目可由知识管理员合并/拆/停用（状态 `active/merged/deprecated`）。

## 5. 嵌入模型（本地）

- **默认本地**：Ollama 托管 `bge-m3`（1024 维，支持中英多语、长文本），或 `bge-small-zh`（384 维，轻量）。
- **归一化**：向量做 L2 归一化，便于余弦/内积统一。
- **可插拔**：云端备选 OpenAI `text-embedding-3-small`；通过配置切换，接口不变。
- **批量嵌入**：切片落库后由后台任务批量调用嵌入网关，失败可重试。

## 6. 存储设计（PostgreSQL + pgvector）

```sql
-- 文档
CREATE TABLE documents (
  id            TEXT PRIMARY KEY,
  title         TEXT,
  source_type   TEXT,
  original_path TEXT,
  parsed_path   TEXT,
  checksum      TEXT,
  tags          TEXT[],
  classification TEXT,
  version       INT,
  imported_at   TIMESTAMPTZ
);

-- 知识条目/切片（向量 + 全文同表）
CREATE TABLE chunks (
  id            TEXT PRIMARY KEY,
  document_id   TEXT REFERENCES documents(id),
  heading_path  TEXT,
  content       TEXT,
  chunk_index   INT,
  keywords      TEXT[],
  facets        JSONB,          -- {domain, applicable_template, source_type}
  confidence    FLOAT,
  status        TEXT,           -- active/merged/deprecated
  embedding     VECTOR(1024),   -- pgvector
  fts           TSVECTOR GENERATED ALWAYS AS (to_tsvector('simple', content)) STORED
);

CREATE INDEX ON chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
CREATE INDEX ON chunks USING GIN (fts);
CREATE INDEX ON chunks (document_id);
```

- `embedding` 用 `ivfflat`（或 `hnsw`）做 ANN；`fts` 做全文检索；`facets` 做分面过滤。

## 7. 混合检索

1. **关键词召回**：`tsvector` 全文 + `keywords`/`facets` 过滤（BM25 风格打分）。
2. **语义召回**：查询文本嵌入后，pgvector 近邻（`ORDER BY embedding <=> :q LIMIT k`）。
3. **融合**：Reciprocal Rank Fusion（RRF）合并两路 Top-K。
4. **重排（可选）**：用轻量 rerank 模型对融合结果精排。
5. **分面过滤**：按 `facets->>'domain'`、`applicable_template` 收窄（撰写时自动注入当前模板类型）。
6. **返回**：结果带 `document_id` + `heading_path` + `chunk_index` 供溯源与引用。

## 8. 溯源

- 检索结果每条回带原文档与 `heading_path`，前端以「引用面板」呈现。
- 撰写生成时把选中条目 `id` 写入 `sections.citations`，导出时转为脚注/批注。

## 9. 增量更新

- 文档更新 → 新版本 → 旧 `chunks` 标记 `deprecated` 并删除向量（或软删），重新切片嵌入。
- 删除文档级联删除其 `chunks`，保持索引一致。

## 10. 本地部署

```yaml
# docker-compose.yml（节选）
services:
  postgres:
    image: pgvector/pgvector:pg16
    environment:
      POSTGRES_DB: baize
      POSTGRES_PASSWORD: localdev
    ports: ["5432:5432"]
  ollama:               # 本地嵌入 + 生成
    image: ollama/ollama
    ports: ["11434:11434"]
    volumes: ["./ollama:/root/.ollama"]
```

- 前端/后端通过 `.env` 指向本地 `POSTGRES_URL` 与 `OLLAMA_URL`；默认不调用任何外部 API。

## 11. 与撰写引擎集成

- 撰写时按当前模板 `type` 自动注入 `applicable_template` 分面，精准召回。
- 每节 `guidance` + `source_tags` 构造查询，调用 `GET /api/kb/search` 取 Top-K，组装进 LLM 提示并生成带引用正文（见 `06_模块设计_按需撰写.md`）。

## 12. 验收要点

- 导入一份 Word/PDF 后能检索到对应知识点，且结果可溯源。
- 断网（仅本地 Ollama）下仍能完成嵌入与检索。
- 文档版本更新后，旧切片不再被召回。
