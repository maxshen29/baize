# 10 · 实现路径分析

> 变更记录：2026-09-18 初版（技术栈锁定 Vue3 + FastAPI + PostgreSQL 后补充分析）。
> 目标：把「框架与文档」推进到「可运行的方案撰写平台」的工程路径。

## 1. 总览

从 M0（文档框架）到 M6（检查/导出）分六步落地。每一步都对应明确的代码模块与可验证产出，避免一次性大爆炸。后端统一 **FastAPI**，前端统一 **Vue3**，数据统一 **PostgreSQL + pgvector**。

## 2. 仓库布局（monorepo）

```
方案系统/
├── web/                 # Vue3 + Vite + TS 前端
│   └── src/
│       ├── api/         # axios 封装，调用 FastAPI
│       ├── views/       # 模板/文档/知识库/撰写/导出 页面
│       ├── components/  # 章节树、检索结果、引用面板等
│       └── stores/      # Pinia（writing task / kb scope）
├── api/                 # FastAPI 后端
│   └── app/
│       ├── main.py      # 应用入口、CORS、路由挂载
│       ├── routers/     # template/document/knowledge/writing/check/export
│       ├── services/    # 领域服务（对应 02_总体架构设计 §3）
│       ├── models/      # SQLModel 表（07_数据模型）
│       ├── infra/       # storage / vector(pgvector) / parser / llm
│       └── schemas/     # Pydantic 入出参
├── db/                  # 数据库
│   ├── migrations/      # Alembic 迁移
│   ├── init/            # enable pgvector、建 FTS/向量索引、seed 模板
│   └── docker/          # postgres+pgvector 镜像参数
├── docker-compose.yml   # 本地一键起 PG+pgvector
└── .env.example         # 配置样例（DB_URL / OLLAMA_URL / LLM_*.）
```

## 3. 里程碑与代码模块映射

| 阶段 | 目标 | 后端（FastAPI） | 前端（Vue3） | 数据 |
| --- | --- | --- | --- | --- |
| M0 ✅ | 框架与文档 | — | — | — |
| M1 | 模板体系（能力①） | `routers/template.py` + `TemplateService` | 模板列表/编辑/章节树 | `templates` 表 |
| M2 | 知识库（能力③） | `routers/knowledge.py` + `KnowledgeService`（切片/检索） | 知识库检索/条目管理 | `documents`+`chunks`(pgvector) |
| M3 | 文档导入（能力②） | `routers/document.py` + `DocumentService`（解析/去重） | 导入/解析预览/版本 | `documents` |
| M4 | 撰写引擎（能力④） | `routers/writing.py` + `WritingService`（LangGraph） | 撰写工作台/章节生成/引用 | `writing_tasks`+`sections` |
| M5 | 检查与导出 | `routers/check.py` + `routers/export.py` | 检查面板/导出按钮 | — |
| M6 | 联调与本地部署 | CORS/健康检查、Docker 化 | 构建打包 | 全量 |

> M1 与 M3 可并行；M2 依赖 M3 的切片来源；M4 依赖 M1+M2。

## 4. 各能力 → 代码模块（FastAPI 路由/服务）

| 能力 | Router | Service | 关键依赖 |
| --- | --- | --- | --- |
| ① 模板 | `/api/templates` | `TemplateService` | `02_模板` 元数据规范 |
| ② 文档 | `/api/documents` | `DocumentService` | `infra/parser` |
| ③ 知识库 | `/api/kb` | `KnowledgeService` | `infra/vector`(pgvector)、嵌入网关 |
| ④ 撰写 | `/api/writing` | `WritingService` | ③ 检索 + LLM 网关 + ① 骨架 |

## 5. 数据迁移与初始化

- **Alembic** 管理 `api/app/models` 到 Postgres 的迁移。
- `db/init/00_enable_pgvector.sql`：`CREATE EXTENSION IF NOT EXISTS vector;`
- `db/init/01_fts_index.sql`：为 `chunks.content` 建 `tsvector` + GIN 索引。
- `db/init/02_seed_templates.sql`：导入 `02_模板` 下 3 个示例标准结构。
- 向量列维度与嵌入模型一致（bge-m3 = 1024）。

## 6. 本地运行步骤

```bash
# 1) 起数据库（含 pgvector）
docker compose up -d            # 启动 postgres+pgvector

# 2) 后端
cd api
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head            # 初始化表与扩展
uvicorn app.main:app --reload   # http://localhost:8000/docs

# 3) 前端
cd web
npm install
npm run dev                     # http://localhost:5173

# 4) 本地嵌入/LLM（可选本地推理）
ollama pull bge-m3 && ollama pull qwen2.5:14b   # 嵌入 + 生成
```

## 7. 依赖与风险

| 风险 | 缓解 |
| --- | --- |
| pgvector 版本与 Postgres 兼容 | 锁定 PG 16 + pgvector 0.7+，compose 固定镜像 |
| 嵌入质量影响召回 | 先 FTS 保底，向量为增强；支持换模型 |
| 长任务（解析/生成）中断 | 任务表持久化 + 轮询/WebSocket 进度 |
| 前端与后端契约漂移 | Pydantic 模型即契约，前端用 OpenAPI 生成类型 |

## 8. 验收标准（每阶段）

- M1：能新建/编辑模板并初始化撰写骨架。
- M2：导入文档后可切片检索，返回带溯源的结果。
- M3：多格式导入成功、去重、版本可查。
- M4：选模板+知识范围可逐章生成并带引用。
- M5：一致性/废标/查重可跑，导出 Word 保留引用。
- M6：本地 `docker compose` + `npm run dev` 一条龙跑通。
