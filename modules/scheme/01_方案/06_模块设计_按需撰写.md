# 06 · 模块设计 · 基于知识库按需撰写（能力④）

> 变更记录：2026-09-18 初版。对应目录 `05_代码`（引擎实现待开发）。

## 1. 职责

- 依据模板与选定知识库，按章节/按需生成方案内容。
- 注入相关知识、插入溯源引用、支持扩写/改写、人工编辑、检查与导出。

## 2. 核心流程（多步编排）

```
选模板 → 初始化撰写骨架(章节树, 见03)
   → 填全局事实(公司名/资质/金额, 一致性约束)
   → 逐章生成:
       对每节: 用 section.guidance + source_tags 检索知识库(见05)
              → 组装提示 → LLM 生成正文
              → 插入引用(溯源) → 落库(章节状态=draft)
   → 人工定稿(编辑/扩写/改写)
   → 检查(一致性/废标项/查重/错别字)
   → 导出 Word/PDF(保留引用)
```

## 3. 撰写任务与章节数据结构（草图）

```yaml
writing_task:
  id: wt_xxx
  template_id: tpl_xxx
  title: XX项目投标方案
  kb_scope: [doc_*, KE_*]      # 限定检索范围
  global_facts:                # 一致性约束
    company: 公司A
    cert_no: ...
  sections:                    # 与模板 sections 对应
    - section_id: s1
      title: 项目理解
      content: ...
      status: draft | review | done
      citations: [KE_20260918_资质]
      version: 3
      updated_at: ...
  status: drafting | reviewing | done
```

## 4. 关键接口（规划）

- `POST /writing-tasks/init`（模板 → 骨架）。
- `POST /writing-tasks/:id/sections/:sid/generate`（单章生成，可带知识范围）。
- `POST /writing-tasks/:id/sections/:sid/expand`（扩写/改写）。
- `PATCH /writing-tasks/:id/sections/:sid`（人工编辑）。
- `POST /writing-tasks/:id/check`（一致性/废标/查重）。
- `POST /writing-tasks/:id/export`（Word/PDF）。

## 5. Agent 编排思路

- 借鉴 OpenBidKit 的 `outlineGenerationTask` + `contentGenerationTask` + `globalFactsTask` + `agentService`。
- 采用「大纲 → 逐章 → 检查」多步编排，每步独立可重试、可恢复（长任务异步落盘）。
- 全局事实在生成前注入系统提示，保证跨章一致。

## 6. 关键设计决策

- **按需而非一次性**：支持选中某章生成，降低 token 成本、便于聚焦。
- **强制溯源**：生成段落默认带 `citations`，可关闭但默认开启。
- **人工闸门**：AI 出 `draft`，`review/done` 需人工操作。
- **引用保留至导出**：Word 中以脚注/批注体现来源。
