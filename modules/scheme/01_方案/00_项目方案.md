# 00 · 项目方案（总体方案）

> 变更记录：2026-09-18 初版，确立平台框架与四大能力。

## 1. 背景与动机

方案类写作（投标、技术建议书、实施方案、可研报告）长期依赖个人经验与手工拼装，存在结构不统一、素材难找、重复劳动、内容难溯源等问题。开源项目 [OpenBidKit_Yibiao](https://github.com/FB208/OpenBidKit_Yibiao) 在招投标场景验证了「模板 + 知识库 + AI 生成 + 检查」的可行性。本平台将其思路抽象为**通用方案撰写平台**，使任意「方案类写作」都能复用同一套框架。

## 2. 平台目标

**一句话**：让「写方案」变成「选模板 → 选知识 → 按需生成 → 人工定稿」的半自动化过程。

具体目标：
- 提供**可复用参考结构模板**，统一章节与写作指引。
- 支持**导入并管理参考文档**，沉淀企业资产。
- 构建**可检索知识库**，让生成内容「有出处」。
- 实现**基于知识库的按需撰写**，降低重复劳动、保证一致性。

## 3. 范围

**In Scope（本次规划 + 后续开发）**
- 四大核心能力：模板、文档管理、知识库、按需撰写。
- 平台文档体系、目录框架、命名规范。
- 本地优先的数据与生成（兼顾隐私与离线）。

**Out of Scope（本期不做 / 远期）**
- 不直接提供 AI 模型训练或大模型服务（仅做网关接入）。
- 不绑定单一招投标业务规则（如各地评标办法），以通用模板表达。
- 不替代人工定稿与法务/商务终审。

## 4. 四大能力定义（依次实现）

1. **可复用参考结构模板**：定义章节骨架与每节写作指引（不含正文）。
2. **导入并管理参考文档**：解析 Word/PDF/网页等，入库、标注、版本管理。
3. **构建可检索知识库**：切片建索引（关键词 + 语义），支持分面检索与溯源。
4. **基于知识库按需撰写**：依模板逐章生成，引用知识、可编辑、可检查、可导出。

## 5. 平台定位与参考借鉴

| 维度 | OpenBidKit（参考） | 本平台 Baize |
| --- | --- | --- |
| 场景 | 招投标专用 | 通用方案写作 |
| 形态 | Electron 桌面端 | Web 优先，桌面可选 |
| 模板 | 模板抽取/存储 | 通用结构模板 + 元数据 |
| 知识库 | `knowledgeBaseStore`+search | 通用知识条目 + 分面/溯源 |
| 生成 | `contentGenerationTask`+Agent | 按需撰写引擎 + 人工定稿 |

借鉴其「本地工作区 + 知识复用 + Agent 编排 + 检查」的成熟范式，但元数据与检索更通用。

## 6. 关键原则

- **可复用**：模板与知识条目均可跨项目复用。
- **可溯源**：生成内容必须能回溯到知识条目/文档。
- **可编辑**：AI 仅出初稿，人工全程可改。
- **本地优先 / 隐私**：原始文档与生成结果默认存本地，可选云端协作。

## 7. 成功指标（定性）

- 新方案起手时间显著下降（模板化）。
- 生成内容可溯源比例 ≥ 90%。
- 知识库检索命中率（人工评估）≥ 80%。

## 8. 阶段路线图（与生成顺序一致）

1. 框架与文档体系（本次）。
2. 能力① 模板体系 + 能力③ 知识库数据结构先行。
3. 能力② 文档导入管线。
4. 能力④ 撰写引擎串联。
5. 检查/导出（一致性、废标项、查重、Word 导出）。

详见 `09_能力与生成顺序Roadmap.md`。

## 9. 风险与取舍

- **检索质量**依赖切片与嵌入策略 → 先支持关键词，再叠语义。
- **生成幻觉** → 强制溯源 + 人工审校闸门。
- **格式还原** → 采用 Open XML / Pandoc 导出，而非纯文本。
